# 机翼应变监测与模型管理系统

## 软件工作流

软件中的模型训练分为两个连续阶段：

### 第1步：模型预训练

输入两类仿真数据：

- 仿真未损伤数据；
- 仿真损伤数据。

预训练阶段生成一个完整的教师模型包：

1. **BP损伤分类模型**：根据48通道应变判断是否存在损伤；
2. **CNN无损回归分支**：预测加载位置 `load_x`、`load_z` 和载荷大小 `load_size`；
3. **CNN损伤回归分支**：预测损伤位置 `damage_x`、`damage_z` 和损伤大小 `damage_size`。

程序会保存 `pretrain_bundle.json`，并同时输出原迁移脚本可直接读取的兼容教师模型文件，例如：

```text
bp_classifier.h5
scaler_X_bp.pkl
cnn_load_x.h5
cnn_load_y.h5
cnn_load_size.h5
cnn_hold_x.h5
cnn_hold_y.h5
cnn_hold_size.h5
```

预训练成功后，该模型自动设为当前迁移学习教师模型。

### 第2步：迁移学习

只有软件检测到有效的预训练模型后，才允许执行迁移学习。

输入四类数据：

- 仿真未损伤；
- 仿真损伤；
- 实际未损伤；
- 实际损伤。

迁移阶段调用当前BP-CNN预训练模型作为教师模型，执行：

```text
AE特征提取 → 知识蒸馏 → 目标域微调 → 生成迁移模型
```

迁移完成后生成待更新模型。点击“更新后台模型”后，在线监测模块才切换到新迁移模型。

## 页面结构

1. 在线监测与应变云图；
2. 第1步：模型预训练；
3. 第2步：迁移学习与更新；
4. 七模型组合导入；
5. 机翼三维模型；
6. 传感器布置。

机翼三维模型、48点传感器坐标、预训练模型和迁移模型分别独立保存，互不覆盖。


## 七模型组合导入

外部训练完成的七个模型可以绕过软件内的预训练和迁移流程，直接导入并应用到在线监测。

七个模型固定对应为：

1. BP损伤分类模型；
2. 无损载荷位置 x 模型；
3. 无损载荷位置 z 模型；
4. 无损载荷大小模型；
5. 有损损伤位置 x 模型；
6. 有损损伤位置 z 模型；
7. 有损损伤尺寸模型。

每一行都可单独选择：

- 模型文件；
- 输入归一化文件（可选）；
- 输出归一化文件（回归模型可选）。

归一化文件留空表示模型直接使用原始48通道输入，或模型直接输出物理量。输入归一化对象需提供 `transform` 方法；回归输出归一化对象需提供 `inverse_transform` 方法。

模型文件支持：

```text
.keras / .h5 / .hdf5
.joblib / .pkl / .pickle / .save
.pt / .pth / .ts / .torchscript
.py
```

软件还提供“选择模型目录并自动匹配”，会根据文件名尝试填写七个模型和归一化文件。自动匹配后必须逐行核对。

点击“检查七个模型”时，软件会依次加载全部七个模型，并使用一组48通道数据同时测试分类模型、无损三模型和有损三模型。点击“导入并应用”后：

```text
BP分类
├─ 无损 → 调用载荷 x、载荷 z、载荷大小三个模型
└─ 有损 → 调用损伤 x、损伤 z、损伤尺寸三个模型
```

坐标输出单位可选择 `m` 或 `mm`，损伤尺寸输出单位可选择 `m` 或 `mm`。载荷大小按 N 使用。机翼三维模型和48点传感器坐标不会被修改。

## 数据列要求

### 48通道输入

支持列名 `1`～`48`，也支持包含对应编号的列名，例如 `strain_1`～`strain_48`。

### 仿真未损伤标签

```text
load_x
load_z 或 load_y
load_size 或 load_n
```

### 仿真损伤标签

```text
hole_x / damage_x / hoald_x
hole_z / hole_y / damage_z / hoald_y
hole_d / hole_d_mm / hole_size / damage_size / hoald_size
```

## 启动

建议使用 Python 3.10 或 3.11。

首次运行：

```text
安装依赖.bat
```

启动软件：

```text
启动软件.bat
```

## 代码文件

- `backend/train_pretrain_bp_cnn.py`：统一预训练脚本；
- `backend/train_transfer_ae_guided_kd_v3.py`：原AE引导知识蒸馏迁移脚本；
- `core/pretrain_backend.py`：预训练任务管理和模型登记；
- `core/keras_v3_backend.py`：迁移学习、模型验证和后台更新；
- `core/external_model_registry.py`：当前外部模型登记与统一推理入口；
- `core/seven_model_group.py`：七模型逐项检查、自动匹配、复制、分支推理；
- `backend/reference/`：用户上传的两份原始训练代码备份。

## 说明

用户上传的回归脚本原始版本只训练一个 `load_x` 单目标MLP/BP回归器。软件中的统一预训练脚本保留其数据读取、归一化、数据划分、训练监控和评估逻辑，并扩展为CNN多任务回归结构，以覆盖无损和损伤状态下的六个目标参数。

## 内置 LC-Kriging 兼容模块

在线监测页面的“应变场重构方法”新增：

```text
LC-Kriging（内置用户代码）
```

该模块由用户提供的七模型联合推理脚本中 `kriging_reconstruct()` 改造而来，并完成以下适配：

- 不再固定使用 6×8 等距坐标，而是读取“传感器布置”页面保存的48个实际坐标；
- 不再固定为600 mm×250 mm矩形板，而是使用当前机翼三维模型生成的计算网格；
- 重构场直接映射到当前三维机翼表面；
- 优先调用 Ordinary Kriging，失败时依次回退至线性RBF和最近邻；
- 七个旧版 Keras 2 / TensorFlow 2.10 模型增加兼容加载，并自动识别 BP 的二维输入与 CNN 的 Conv1D 三维输入。

模型识别和应变重构相互独立：七模型负责判断损伤并预测参数，LC-Kriging模块负责将48点应变重构为连续场。

> 代码核对说明：用户上传脚本中的 `kriging_reconstruct()` 实际调用 Ordinary Kriging / RBF / 最近邻，预测载荷并未传入变差函数或插值方程。因此本软件保留其原始计算逻辑并作为“用户代码兼容版”集成；若需要严格复现论文中载荷控制项，还需要补充载荷控制的具体公式或对应源代码。
